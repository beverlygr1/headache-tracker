# Дневник самочувствия в Flutter

Клиент использует поля API из миграции `0003_diary_headache`: наличие боли
(`true`/`false`/`null`), качество сна (1–10) и кофеин (мг). Длительность сна,
вода и стресс сохранены.
Незаполненная отметка боли остаётся `null`; отсутствие боли записывается только
после явного выбора «Нет, не было».

День открывается с экрана «Сегодня» или из списка самочувствия в «Дневнике».
При открытии клиент заново читает запись по дате. Изменение воды или другого
поля отправляет полное состояние полей формы, поэтому предыдущие ответы
сохраняются. Координаты в форме не редактируются и не отправляются, чтобы не
стереть их при обновлении. После сохранения пользователь остаётся на той же
вкладке; при ошибке сети форма и её ввод остаются на экране для повтора.

Для текущей базы перед запуском клиента нужна миграция
`backend/alembic upgrade head`; Docker Compose выполняет её при старте.
Локальные проверки: Flutter analyze, 43 Flutter теста, web build, 52 backend
теста. Отдельные тесты покрывают повторное открытие и изменение дневника,
отметку отсутствия боли, явные `null` в запросе, повтор сохранения после
ошибки сети и завершение приступа с сохранением исходного ID.

Figma MCP не вернул слои или скриншот исходного файла из-за текущих прав
доступа. Форма использует существующие карточки, типографику и цвета проекта;
точное совпадение с исходным макетом остаётся непроверенным.
