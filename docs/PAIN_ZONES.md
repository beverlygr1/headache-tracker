# Зоны боли и проверка записи

Экраны добавлены в ветке `Front_flutter` поверх существующих экранов
онбординга, дневника самочувствия и шрифта Onest.

## Экраны

Визуальная основа — макет Figma:
https://www.figma.com/design/0KGFylUdydJwTlkxbIoqrl/?node-id=249-2

- `PainZonesPage`: пустое состояние, вид спереди и вид сзади.
  Выбор работает по областям головы и по текстовым кнопкам.
  Поддерживаются «Лоб», «Виски», «Темя» и «Затылок»; выбранные зоны
  можно убрать отдельными кнопками. Переключение вида сохраняет выбор.
- `AttackReviewPage`: время начала, интенсивность, число и названия зон,
  симптомы, подсказка о последующем редактировании и сохранение.
- `AttackEntryPage`: переход к схеме и проверке, выбор нескольких зон,
  сохранение пользовательских областей и симптомов.

При нажатии «Продолжить» форма открывает проверку. Если зоны ещё не выбраны,
сначала открывается схема. Запись создаётся или обновляется только на экране
проверки после нажатия «Сохранить приступ». Возврат с проверки сохраняет
заполненную форму; возврат со схемы отменяет только её неподтверждённый выбор.
На время сохранения повторные нажатия и возврат блокируются. При ошибке
данные остаются доступны, а сохранение можно повторить.

Все страницы используют существующую тему, шрифт Onest и компоненты проекта.
Основное содержимое прокручивается, нижняя кнопка остаётся доступной.
Выбранные области имеют семантические подписи для средств доступности.

## Бэкенд

Проверены модели, схемы, API и мобильный слой запросов.
Существующий бэкенд поддерживает нужные данные:

| Действие | API |
| --- | --- |
| Создать приступ | `POST /api/v1/attacks` |
| Изменить приступ | `PUT /api/v1/attacks/{id}` |
| Повторно прочитать | `GET /api/v1/attacks/{id}` |
| Показать дневник | `GET /api/v1/attacks` |

Пример тела запроса:

```json
{
  "start_time": "2026-10-08T02:30:00Z",
  "intensity": 6,
  "localization": "Лоб, Затылок",
  "symptoms": ["Тошнота"]
}
```

`AttackDraft` держит выбор в списке, а перед отправкой соединяет названия
через `, `. Старые одиночные локализации продолжают открываться в форме.
Общая длина `localization` ограничена 120 символами на клиенте и сервере.
Время передаётся в UTC существующим API-слоем. Обновление зон не меняет
время завершения и другие поля приступа. Доступ ограничен владельцем записи.

Новых серверных методов или таблиц для этих экранов не требуется.
Добавлены интеграционные тесты серверного контракта. Для запуска свежей
версии проекта нужны миграции до `0003_diary_headache`:
`alembic upgrade head`.

собранного приложения в браузере не завершена. Полные Flutter-проверки выше
выполнены пользователем и подтверждены журналами, а не только скриншотом.
Для повторной проверки в обычном терминале из `mobile/` выполняются:

```powershell
flutter pub get
flutter analyze
flutter test
flutter build web
```

Для автоматического запуска этих проверок в обычной Windows-среде откройте
`scripts/verify_flutter.cmd`. Скрипт по очереди проверяет SDK, зависимости,
анализ, тесты и сборку web с `DEMO_MODE=true`. Останавливается при первой
ошибке, сохраняет журналы и `result.json` в `verification/`.
Flutter ищется в PATH, `FLUTTER_ROOT` и установленном для этой задачи
каталоге `Documents/Codex/tools/flutter`. Если SDK находится в другом месте:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify_flutter.ps1 -FlutterSdk C:\path\to\flutter
```

Если Flutter SDK установлен другим локальным пользователем, скрипт передаёт
Git точечное разрешение `safe.directory` на каталог этого SDK через окружение
процесса. Разрешение действует только при запуске скрипта и его дочерних
команд; глобальная конфигурация Git не меняется. Настройки окружения
восстанавливаются при завершении. Это нужно для внутренних Git-команд Flutter.
Скрипт не отправляет файлы в репозиторий. Его синтаксис проверен.

Для открытия приложения в Chrome запустите `scripts/run_demo.cmd`.
Он использует тот же временный доступ Git к SDK и запускает
`flutter run -d chrome --dart-define=DEMO_MODE=true`.
Окно терминала нужно оставить открытым, пока работает приложение;
для завершения нажмите `q` в этом окне. Результат запуска сохраняется
отдельно в `verification/demo-result.json`, журнал — в `demo.log`;
итог успешно выполненной проверки не перезаписывается.

## Ограничение рисунка

Из публичного просмотра Figma удалось увидеть экраны, но подключение
не предоставило исходный ресурс рисунка головы и точные свойства слоёв.
`PainHeadMap` содержит интерактивную схему, нарисованную средствами Flutter.
Это приближение к рисунку в макете; точное визуальное совпадение не проверено.
Геометрия подсветки и нажатий совпадает. Новые зависимости для рисунка
не добавлены.
