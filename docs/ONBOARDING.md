# Онбординг после авторизации

Ветка: `feature/post-auth-onboarding`. Основа: `dev`, коммит `da0f772`.

Визуальная основа — страница **Design** в Figma:
https://www.figma.com/design/0KGFylUdydJwTlkxbIoqrl/?node-id=249-2
Использованы существующие `AppColors`, `AppCard`, кнопки и навигация Flutter.
Локально подключён Onest (SIL OFL; лицензия рядом со шрифтом).
Новые экраны реализованы в приложении; Figma-файл не изменялся.

## Сценарий

1. После регистрации или входа профиль определяет, нужно ли знакомство.
2. «Начнём с вашего самочувствия» объясняет дневник, приступы и историю.
3. «С чего начнём?» предлагает записать приступ или самочувствие.
4. «Позже» и «Перейти на главную» завершают знакомство и открывают «Сегодня».
5. Прогресс сохраняется на аккаунте: после прерывания открывается сохранённый
   шаг, после завершения повторное знакомство автоматически не запускается.
6. В профиле знакомство можно открыть повторно без изменения серверного флага.

Форма самочувствия сохраняет сон, воду и стресс через существующий дневник
факторов. Поля необязательны, но нужна хотя бы одна отметка. Десятичная запятая
поддерживается. При ошибке текст остаётся на экране; сохранение можно повторить.
Существующую запись можно открыть и исправить. Другие факторы (качество сна,
кофеин и координаты) эта форма не изменяет.

Карточка на «Сегодня» и раздел «Самочувствие» в дневнике показывают сохранённые
записи. Пустой дневник предлагает первую запись. Фиктивные «7 дней наблюдений»
и индикатор прогноза убраны: `/forecast/risk` пока отвечает 501, поэтому интерфейс
честно сообщает, что прогноз появится на следующем этапе.

Напоминания и системные уведомления в эту версию не включены: в проекте пока
нет сервиса их планирования. Главный путь первой записи полностью работает.

## Бэкенд и обновление базы

**До запуска нового мобильного клиента обновите бэкенд и примените миграцию.**

```bash
cd backend
alembic upgrade head
```

В Docker Compose миграция выполняется при старте сервиса:

```bash
docker compose up --build -d
```

Миграция `0002_onboarding` добавляет в `users`:

- `onboarding_step`: 0 (знакомство) или 1 (первое действие);
- `onboarding_completed`: завершено или пропущено знакомство.

Для существующих аккаунтов с приступами или дневником знакомство считается
завершённым. Пустые и новые аккаунты начинают с шага 0. Записи не удаляются.
Миграция обратима: `alembic downgrade 0001_initial` убирает только новые поля.

`GET /api/v1/user/profile` возвращает оба поля.
`PUT /api/v1/user/onboarding` принимает:

```json
{"step": 1, "completed": false}
```

Для завершения: `{"step": 1, "completed": true}`. Нужен Bearer JWT. Ответ —
обновлённый профиль. Неверные шаги, null, несовместимые типы и лишние поля дают
422. Меняется только аккаунт владельца токена. Завершение необратимо через этот
endpoint; запоздалое обновление шага не может сбросить завершённое знакомство.

## Запуск и просмотр

Обычный запуск с авторизацией и реальной БД:

```bash
cd mobile
flutter pub get
flutter run -d chrome --dart-define=API_BASE_URL=http://127.0.0.1:8000/api/v1
```

Для просмотра онбординга без бэкенда и учётных данных:

```bash
cd mobile
flutter pub get
flutter run -d chrome --dart-define=ONBOARDING_DEMO=true
```

В этом режиме дневник изначально пуст, записи хранятся только в памяти и
сбрасываются при перезапуске. Для реальных пользователей этот флаг не передавать.
Существующий `DEMO_MODE=true` сохраняет прежний сценарий демонстрации.

## Проверка

```bash
cd mobile
flutter analyze
flutter test
flutter build web --release --no-web-resources-cdn
```

```bash
cd backend
pip install -r requirements-dev.txt
pytest -q
```

Тесты покрывают сохранение и восстановление прогресса, пропуск, повторный
вход, разделение аккаунтов, запоздалые ответы после смены аккаунта, истечение
сессии поверх формы, открытие первой записи, ошибки сохранения и узкий экран
с увеличенным текстом. API-тесты используют изолированную SQLite, как и
существующий тестовый набор; рабочая БД остаётся PostgreSQL. Миграция проверена
на upgrade/downgrade с сохранением истории и генерацией PostgreSQL SQL.

Проверено с Flutter 3.47.5 / Dart 3.13.4, Python 3.12.

## Передача через Git

ZIP содержит исходники текущей ветки. Для сохранения полной истории и всех
веток рядом передаётся файл `headache-tracker-all-branches.bundle`.

```bash
git clone -b feature/post-auth-onboarding headache-tracker-all-branches.bundle headache-tracker
cd headache-tracker
git remote set-url origin https://github.com/beverlygr1/headache-tracker.git
git push -u origin feature/post-auth-onboarding
```

После проверки создайте Pull Request из новой ветки в `dev` — она является
актуальной базой работы. Не заменяйте `dev` или `main` архивом целиком.
Внутри рабочей локальной копии изменения уже находятся в отдельной ветке.
